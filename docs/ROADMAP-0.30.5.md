# 项目定位与后续规划

VIE 的定位是 Harness 对话中的通用可视化与本地交互层。模型决定画什么，使用 SVG、Canvas 或需要时的 Three.js 自由表达；引擎负责统一控件、渲染隔离、状态、预览与修订；长篇解释保留在 Harness 正文。学习模式是在这套能力上组织阶段、应用与测验，不是限定学科的模板集。

通用绘图、共享按钮和读数、学习阶段、练习题、图文交替、增量预览、局部修复和离线三维已经存在。下一步应提高首次成功率和可读性，避免通过不断加入领域模板来扩大范围。

| 优先级 | 发现与证据 | 后续动作及验收 |
| --- | --- | --- |
| 本版已修复 | 容器固定 760px；静态图为字号自动撑宽，导致右侧落入隐藏滚动区域 | 卡片跟随正文，完整 SVG 适配；宽窄屏、窄面板、展开/收起回归 |
| 本版已实现 | 用户选定 A，重点统一按钮、滑块等组件 | 共享中性组件规范；保持图形布局独立，并验证原生/隔离视图、键盘、深色模式与状态同步 |
| P0 待做 | 本地意图探针中，“运行 npm test，然后用图解释失败原因”仍进入讲解快路径，失去所需操作工具 | 仅高置信度纯讲解启用快路径；混合操作保留宿主能力。覆盖先操作后解释、纯知识讲解与续接；不增加一次模型分类请求 |
| P1 待做 | 普通工具指引仍带有热锻等特定历史案例文字 | 保留坐标、单位、假设及数据一致性的通用规则，把学科案例移入可选示例和测试；测量常驻提示体积，验证历史输入兼容 |
| P1 待做 | 布局检查只能提示重叠/越界，无法指出具体对象及修复位置 | 对引擎拥有的标签与控件输出对象位置和边界证据；优先确定性布局，再进行有限局部修复；不移动科学曲线来掩盖错误 |
| P1 待核实/修复 | 展开层的 Escape 监听在父文档，焦点进入隔离 iframe 后可能无法收起 | 增加 iframe 内真实键盘回归；只接受来自当前 iframe 且通道匹配的关闭请求，恢复原触发器焦点 |
| P1 待做 | 软件门禁没有真实模型调用，不能据此断言生成速度或知识正确率 | 使用既有 48 题及 16 道保留题，对同一宿主/模型测首次有效图、结束耗时、token、修复次数和人工审核；报告 p50/p95，保留失败样本 |
| P2 待做 | 版本标记和交付路径分布在多个构建、测试文件 | 将版本与构建标识集中管理，安装后诊断显示版本及构建摘要，区分旧包缓存与新改动 |

二维仍适合作为常见解释的默认表现；空间关系确实需要三维时再使用三维。避免增加不必要按钮、强制多图、多次模型调用或整套重写。更强模型可以改善内容和代码，但稳定布局、契约校验、统一交互和明确错误反馈应该由引擎承担。

本版没有实施表中的待做项，也没有发布 Git、市场 PR 或远程 Release。
